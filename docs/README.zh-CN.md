# 把创意做成单片机小产品

**带着想法来，做出可以使用的实物。**

告诉 AI 你希望产品怎样工作，它会理清需求，并利用实际可用的工具承担方案、材料、代码、仿真、烧录和调试。你不需要先学会单片机编程，也不必管理代码才能开始。

优先使用你已有的硬件和软件。你会拿到可勾选的材料清单、适合所在地区的参考购买链接、清晰接线图片和简短实物操作步骤。AI 根据当前项目选择有用的检查，通常在后台完成，并在实物运行前核对电气设计。

提醒器、控制器、传感装置，都可以从你想要的行为开始。路线取决于你的目标与实际可行性，不按知识水平人为限制作品难度；通过明确的阶段成果，逐步得到可用实物，以及继续使用和改进它所需的资料。

## 主对话聊产品，代码交给编程代理

主对话聚焦你想做的产品、关键选择和下一个有用结果。平台支持子代理时，由同一个能力合适的编程子代理持续负责源码阅读与修改、构建、测试和调试。主代理只接收简短结果、检查与证据路径、限制和你的下一步动作，不把整份源码、差异或原始日志堆进产品讨论。你想了解代码时，AI 再取出相关的小段解释。

可重复的标准工作优先交给脚本。两个产品入口都自带完全相同、可独立使用的 Python 标准库工具 `scripts/mcu_project.py`。AI 根据对话和已核实事实维护可选的项目本地 `mcu-project.json`，涵盖需求、材料数量与规格、接线与引脚绑定、现有测试/烧录配置、购物观察、行为验收、进度和交付文件。你无需填表、改 JSON 或管理新登记系统。原生 Projects 和工程记录继续使用，五个 Skill 入口及安装方式保持不变。

| 命令 | 能得到什么 |
| --- | --- |
| `validate` | 检查已提供的信息或只检查当前阶段；无关信息缺失不挡住有用工作。 |
| `export --for test\|flash\|shopping` | 复用现有执行器输入；购物按实物库存计算缺口，例如需要五个、已有三个，只需补两个，保留原样规格、购物车快照与未知项。 |
| `wiring` | 同一份明确接线数据生成 SVG、编号表和 `pins.generated.json`；电气未知项继续待确认。 |
| `acceptance` | 生成实用行为清单，区分未运行、通过、失败和待确认；通过或失败须绑定已有证据。 |
| `diagnostics` | 只对明确允许的现有日志/报告做有界摘要，不连接设备，也不执行日志中的命令。 |
| `package` | 按明确文件清单生成本地 ZIP，附哈希及项目/版本关联，拒绝过期、缺失或可识别的私密输入。 |

编程子代理复用当前工具缓存与执行器接口；硬件、购物车、安装和发布的授权仍由主代理掌握。默认最多并行两个子代理，同一文件范围只有一个写入者。平台真实提供模型选择时，简单批量工作可用轻量模型；否则如实继承默认模型。没有子代理功能也能继续，由主代理使用精简工具摘要完成。

详见[工具契约与限制](../skills/build-with-ai-mcu/references/project-tools.md)和[可运行的虚构示例](../skills/build-with-ai-mcu/assets/project-example/mcu-project.json)。AI 仍须检查真实 C/C++ 与引脚绑定是否一致，并查看接线图。逻辑接线图或宿主机测试通过不等于电气与实物成功。秘密检测不能穷尽全部情况，打包前仍要审阅选定内容；本地 ZIP 不代表允许公开发布。

## 从想法到作品

1. **理清目标。** 讨论想要的行为与验收效果。相关记忆包括工具、经验、聊天偏好、学习方式和小习惯；当前表达优先，不要求先填预算或风格问卷。
2. **优先复用。** 先查代码、配置、接口与已有硬件。新选 MCU 和模块时优先考虑适合且有明确仿真支持的组合，不为方便随意换掉已有可用板子。
3. **看清买什么。** 材料面板显示规格、数量、已有材料、缺件及预计新增费用。地区购买链接仅供参考，也可以买其他店铺的同规格材料。
4. **AI 实现与验证。** AI 用现有工具写代码、编译和修复，按实际需要选择测试或仿真；愿意自己写时可用协作入口。不要求你完成课程或管理代码改动。
5. **接线与试运行。** 提供核对过的图片和对应文字，按实际情况安排断电接线与开发板烧录。每次只交代一个短操作、预期效果和反馈点，同一目标已有授权继续复用。
6. **保留自己的成果。** 交付源码、接线、实际产生的测试或仿真资料、简短说明和已知限制。你的作品保留私密还是开源，由你决定。

交流跟随你的节奏，不反复追问，不跑题；下一步已明确就开始做。需求、工具和材料允许时，争取几天内得到可用成果，但不承诺每个想法都能按固定天数完成，也不把所有人限制在固定入门项目里。

## 检查、预览与首次运行

不是所有项目都要跑测试或仿真。AI 根据实际不确定性和风险决定需要哪些检查，默认使用现有工具在后台运行。你想先看效果再烧录时，可以提供浏览器预览或渲染画面。流程随当前需求调整，不要求固定顺序。

实际运行的检查保留对应代码、接线版本和结果。编译、普通逻辑测试或网页样机不等于 MCU 仿真；带外设替身的 ARM 指令执行能覆盖实际跑过的代码路径，但不能证明整块开发板或电气行为。相关改动需要时，重新检查受影响部分。

仿真不能证明完全没有错误或绝不会损坏硬件。还需单独核对实际供电、极性、电平、电流、限流、驱动和负载限制。编译、逻辑测试、MCU 仿真、电气核对、烧录读回与实物效果分别报告。

已有板子或模块没有合适模型时，只要满足目标就继续使用。AI 说明相关验证缺口，利用现有工具继续安全、有效的工作。核实目标、电气条件并获得对应授权后，可隔离外部负载，先给开发板供电做烧录与诊断。这不能证明整机正常，也不能直接跳到满负载运行。详见[验证规则](../skills/build-with-ai-mcu/references/verification.md)。

## 安装与开始

在 GitHub 选择 **Code → Download ZIP**，或运行：

```sh
git clone https://github.com/boyan-xu/build-with-ai-mcu.git
```

从 `skills/` 中选择需要的完整技能文件夹，放入所用工具支持的技能目录。两个制作入口是 `build-with-ai-mcu`、`develop-with-ai-mcu`，三个工具入口是 `test-mcu-in-background`、`flash-mcu-firmware`、`select-products-to-cart`。Codex 优先使用已设置的 `$CODEX_HOME/skills`，否则使用 `~/.codex/skills`。已有同名技能时先检查再替换；必要时刷新发现或开启新会话。每个入口自带资源，各有一份适用于三语的指令；可用工具随平台变化。

`select-products-to-cart` 也可单独安装。材料清单列好后，AI 只问一次是否需要在指定网站代选缺件并加入购物车，你仍可只要购买链接。面板里的独立加购按钮会发送这项明确请求，页面本身不会访问商店。

```text
用 $build-with-ai-mcu。做一个门打开超过 30 秒就响的提醒器。
技术工作由你处理，我已有 ESP32 和 Arduino IDE，帮我做出可用成果。
```

```text
用 $develop-with-ai-mcu。继续我已经能运行的 STM32 工程，增加 PWM 控制。
我想自己写代码，先检查现有定时器配置，再帮我确定下一步最小改动。
```

没方向时可要五个合适的候选；已有材料或半成品就从那里继续。阶段任务应通向自己的目标，不把它换成无关练习。

## 随包工具与证据

- **代选加购，不下单：**[选购 Skill](../skills/select-products-to-cart/SKILL.md)结合浏览器实查与[无需额外依赖的比价脚本](../skills/select-products-to-cart/references/workflow.md)。AI 核对具体规格、包装数量、配送及商品加运费的费用，在合格候选里选合适的一款，再按购物车现状只补齐相同规格的缺口。保留其他商品，止于购物车，不结算、不下单、不支付、不接受订阅。运费或关键规格未知时保留待确认，不冒充全网最低价；登录状态与网站能力可能限制自动化。开发验证使用本地虚构商店，不涉及真实购物账户。

- **可复用的执行工具：**[后台测试脚本](../skills/test-mcu-in-background/references/workflow.md)可运行已有软件检查，或编译并执行 Cortex-M 的 C 测试，还能按需导出 OLED 缓冲区图片。[烧录脚本](../skills/flash-mcu-firmware/references/workflow.md)默认只做离线预检查，实际写入时使用已有 STM32、ESP 或 Arduino 工具。项目配置由 AI 准备，用户不必编辑脚本或 JSON。需要 Python 3.10 及以上；ARM 依赖首次准备后复用私有缓存，不再每次搭环境。编译器与兼容烧录软件仍需实际可用，必要安装提前说明；脚本不承诺无需适配就能模拟所有外设或支持任意板子。

- [材料面板](../skills/build-with-ai-mcu/assets/parts-checklist.html)及[集成说明](../skills/build-with-ai-mcu/references/checklist.md)：可在支持的聊天面板或独立网页中勾选并保存有效进度。购买请求优先使用聊天接口，否则显示可复制文字；页面不会暗中联系商店或 AI。
- [低压示例](../skills/build-with-ai-mcu/references/uno-led/README.md)：图片、连接定义、代码与仿真图一致，并附绑定测试文件版本的[真实 MCU 仿真记录](../skills/build-with-ai-mcu/references/uno-led/simulation-result.json)。启动与数字输出检查已在 Wokwi 通过，没有测试真实硬件或证明电气安全。这是对应场景的证据，不是必做的入门作品。
- [REA 可选流程](../skills/build-with-ai-mcu/references/rea.md)：复现产品功能时按需复用可用的 [REA](https://github.com/morluto/rea)，确有需要且缺少时才询问接入；不安装不妨碍普通项目。商用或发布前查清权利，工具可用不代表有权分发专有代码或素材。

## 结构范围与实际边界

当前版本默认不交付自动 CAD 建模、可打印结构设计或直接打印。有外壳需求时优先现成外壳、现有结构或用户提供的模型。已有建模能力、打印机和 CNC 仍是相关背景；未来自动建模与打印流程需明确更新 Skill 后加入，不因模型自评能力提升而自动启用。

AI 需要实际可用的工具连接才能编译、调试、仿真或访问硬件。必要下载、账户和费用提前说明。网页烧录仍需兼容硬件和本地访问，不保证所有环境零安装。私人凭据、记忆和工程记录不进入公开资料。这是做产品的工作方式，不是固定单片机课程。

## 检查源码

运行 `node --test tests/*.test.mjs` 检查面板、打包、连接及仿真记录一致性。技能格式可用官方 [skill-creator 校验器](https://github.com/openai/skills/tree/main/skills/.system/skill-creator)检查。自动测试与记录的 MCU 运行分开，也不能代替实物测试。

运行 `python -B -m unittest discover -s tests -p "*_test.py"` 检查环境复用、运行失败处理、离线烧录适配及 OLED 导出资料。烧录测试使用模拟的厂商进程，不访问实物；真实 ARM 样例的独立运行证据见后台工具说明。
