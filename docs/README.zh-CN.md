# 把创意做成单片机小产品

**带着想法来，做出可以使用的实物。**

告诉 AI 你希望产品怎样工作，它会理清需求，并利用实际可用的工具承担方案、材料、代码、仿真、烧录和调试。你不需要先学会单片机编程，也不必管理代码才能开始。

优先使用你已有的硬件和软件。你会拿到可勾选的材料清单、适合所在地区的参考购买链接、清晰接线图片和简短实物操作步骤。AI 根据当前项目选择有用的检查，通常在后台完成，并在实物运行前核对电气设计。

提醒器、控制器、传感装置，都可以从你想要的行为开始。路线取决于你的目标与实际可行性，不按知识水平人为限制作品难度；通过明确的阶段成果，逐步得到可用实物，以及继续使用和改进它所需的资料。

## 从想法到作品

1. **理清目标。** 讨论想要的行为与验收效果。相关记忆包括工具、经验、聊天偏好、学习方式和小习惯；当前表达优先，不要求先填预算或风格问卷。
2. **优先复用。** 先查代码、配置、接口与已有硬件。新选 MCU 和模块时优先考虑适合且有明确仿真支持的组合，不为方便随意换掉已有可用板子。
3. **看清买什么。** 材料面板显示规格、数量、已有材料、缺件及预计新增费用。地区购买链接仅供参考，也可以买其他店铺的同规格材料。
4. **AI 实现与验证。** AI 用现有工具写代码、编译和修复，按实际需要选择测试或仿真；愿意自己写时可用协作入口。不要求你完成课程或管理代码改动。
5. **接线与试运行。** 提供核对过的图片和对应文字，按实际情况安排断电接线与开发板烧录。每次只交代一个短操作、预期效果和反馈点，同一目标已有授权继续复用。
6. **保留自己的成果。** 交付源码、接线、实际产生的测试或仿真资料、简短说明和已知限制。你的作品保留私密还是开源，由你决定。

交流跟随你的节奏，不反复追问，不跑题；下一步已明确就开始做。需求、工具和材料允许时，争取几天内得到可用成果，但不承诺每个想法都能按固定天数完成，也不把所有人限制在固定入门项目里。

## 检查、预览与首次运行

不是所有项目都要跑测试或仿真。AI 根据实际不确定性和风险决定需要哪些检查，默认使用现有工具在后台运行。你想先看效果再烧录时，可以提供浏览器预览或渲染画面。流程随当前需求调整，不要求固定顺序。

实际运行的检查保留对应代码、接线版本和结果。编译、普通逻辑测试或网页样机不等于 MCU 仿真；带外设替身的 ARM 指令执行能覆盖实际跑过的代码路径，但不能证明整块开发板或电气行为。相关改动需要时，重新检查受影响部分。

仿真不能证明完全没有错误或绝不会损坏硬件。还需单独核对实际供电、极性、电平、电流、限流、驱动和负载限制。编译、逻辑测试、MCU 仿真、电气核对、烧录读回与实物效果分别报告。

已有板子或模块没有合适模型时，只要满足目标就继续使用。AI 说明相关验证缺口，利用现有工具继续安全、有效的工作。核实目标、电气条件并获得对应授权后，可隔离外部负载，先给开发板供电做烧录与诊断。这不能证明整机正常，也不能直接跳到满负载运行。详见[验证规则](../skills/build-with-ai-mcu/references/verification.md)。

## 安装与开始

在 GitHub 选择 **Code → Download ZIP**，或运行：

```sh
git clone https://github.com/boyan-xu/build-with-ai-mcu.git
```

把需要的完整技能文件夹（`skills/build-with-ai-mcu`、`skills/develop-with-ai-mcu`，可一个或两个）放入所用工具支持的技能目录。Codex 优先使用已设置的 `$CODEX_HOME/skills`，否则使用 `~/.codex/skills`。已有同名技能时先检查再替换；必要时刷新发现或开启新会话。每个入口自带资源，各有一份适用于三语的指令；可用工具随平台变化。

```text
用 $build-with-ai-mcu。做一个门打开超过 30 秒就响的提醒器。
技术工作由你处理，我已有 ESP32 和 Arduino IDE，帮我做出可用成果。
```

```text
用 $develop-with-ai-mcu。继续我已经能运行的 STM32 工程，增加 PWM 控制。
我想自己写代码，先检查现有定时器配置，再帮我确定下一步最小改动。
```

没方向时可要五个合适的候选；已有材料或半成品就从那里继续。阶段任务应通向自己的目标，不把它换成无关练习。

## 结构范围与实际边界

当前版本默认不交付自动 CAD 建模、可打印结构设计或直接打印。有外壳需求时优先现成外壳、现有结构或用户提供的模型。已有建模能力、打印机和 CNC 仍是相关背景；未来自动建模与打印流程需明确更新 Skill 后加入，不因模型自评能力提升而自动启用。

AI 需要实际可用的工具连接才能编译、调试、仿真或访问硬件。必要下载、账户和费用提前说明。网页烧录仍需兼容硬件和本地访问，不保证所有环境零安装。私人凭据、记忆和工程记录不进入公开资料。这是做产品的工作方式，不是固定单片机课程。

## 检查源码

运行 `node --test tests/*.test.mjs` 检查面板、打包、连接及仿真记录一致性。技能格式可用官方 [skill-creator 校验器](https://github.com/openai/skills/tree/main/skills/.system/skill-creator)检查。自动测试与记录的 MCU 运行分开，也不能代替实物测试。

## 许可证

运行 `python tests/showcase_test.py` 检查 OLED 导出资料、文件校验值、接线与源码对应、链接及照片元数据，不访问硬件。
